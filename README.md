# Сила и КБЖУ — PWA для учёта тренировок и питания

Личное приложение для iPhone (Safari → «Добавить на экран Домой»).
Чистые HTML + CSS + JavaScript (ES-модули), без сборщиков, npm, фреймворков и CDN.
Все данные хранятся в IndexedDB в браузере, приложение работает офлайн.

## Как запустить на компьютере

ES-модули не работают из `file://`, поэтому нужен любой локальный http-сервер.

- **VS Code + Live Server**: правый клик по `index.html` → «Open with Live Server».
- **Python**: `python -m http.server 8080` в папке проекта → http://localhost:8080

Service worker активен на `localhost` и `https`, поэтому офлайн-режим проверяется
именно так (не из `file://`).

## Как поставить на iPhone

Приложению нужен **https**-адрес: Safari не регистрирует service worker по локальной
сети без https. Проще всего — GitHub Pages (бесплатно для публичных репозиториев).

### Публикация на GitHub Pages

1. Создайте репозиторий на GitHub (например, `fitness-pwa`).
2. Залейте **содержимое папки `fitness-pwa`** в корень репозитория: в корне должны
   лежать `index.html`, `app.js`, `sw.js`, `manifest.webmanifest` и папки `icons/`, `tools/`.
   ⚠️ Заливайте **только папку `fitness-pwa`**. Вся папка `clineai` не годится: рядом
   с проектом лежат рабочие выгрузки с персональными данными (ФИО, телефоны, ИНН),
   профили браузеров с cookies и токенами, резервные копии. В публичном репозитории
   они станут доступны всем, и удалить их из истории git потом сложно.
   Если всё-таки залили всю папку, приложение окажется в подпапке и адрес станет
   `https://<логин>.github.io/<репозиторий>/fitness-pwa/` — работать будет, но корень
   репозитория удобнее (и безопаснее).
3. `Settings` → `Pages` → `Source: Deploy from a branch`, `Branch: main`,
   папка `/ (root)` → `Save`.
4. Через 1–2 минуты откройте `https://<логин>.github.io/<репозиторий>/` в Safari на iPhone.
5. «Поделиться» → «Добавить на экран Домой».
6. Первое открытие — с интернетом: файлы кэшируются, дальше приложение работает офлайн.

Все пути в проекте относительные (`./`), поэтому приложение одинаково работает и в
корне домена, и в подпапке репозитория. Файл `.nojekyll` в корне отключает сборку
Jekyll на GitHub Pages — статика отдаётся как есть.

### Обновления после правок кода

Версию кэша менять **не нужно**: `sw.js` работает по стратегии **network-first** —
файл, который есть в сети, всегда приходит свежим и обновляет копию в кэше.

1. Закоммитьте и запушьте в ветку `main`.
2. На iPhone откройте приложение **с интернетом**: при запуске оно само проверяет
   обновление service worker (`registration.update()`), а страница и модули
   запрашиваются заново с перепроверкой на сервере.
3. Что версия сменилась, видно по тосту «Пришло обновление — закройте и откройте
   приложение», по строке `[app] Версия сборки: …` в консоли Safari и по бейджу
   версии в карточке «Данные» на экране «Профиль» (константа `APP_VERSION`
   в `version.js`).

`CACHE_VERSION` в `sw.js` поднимают только в одном случае — когда нужно принудительно
выбросить весь кэш (например, поменялся состав файлов и старые записи мешают).
Новый файл приложения обязательно добавьте в `APP_FILES`, иначе в офлайне его не будет.

> На этапе 7 `CACHE_VERSION` поднят с `v4` до `v5`: изменились `index.html`
> (появились CSP и `referrer`), `nutrition.js` (полоски прогресса считаются
> через CSSOM) и `sw.js`. Так у всех, кто уже установил приложение, старый
> кэш удаляется при активации нового service worker и не мешает обновлению.

> **Данные не переезжают между адресами.** IndexedDB привязана к адресу сайта: записи,
> сделанные на `http://127.0.0.1:8080`, на `https://<логин>.github.io/...` не появятся
> (и наоборот). Перенос делается вручную: «Профиль» → «Сохранить копию в файл»
> (или «Показать JSON» → «Копировать»), а на новом адресе — «Загрузить из файла».

> Если после обновления всё равно видна старая версия — удалите иконку с домашнего
> экрана и добавьте заново: iOS иногда держит старый слепок приложения.

## Экран «Тренировки» (этап 2)

- **Справочник упражнений ведёт сам пользователь**: приложение не подставляет готовый
  список. В шапке/внизу экрана кнопка «📚 Справочник упражнений» — там добавление,
  переименование, удаление и полная очистка.
- **Дата всегда выбирается вручную**: «+» в шапке → дата (по умолчанию сегодня,
  можно любую прошлую или будущую) и заметка. Дату можно поменять и в самой тренировке.
- **Подходы** записываются как «вес × повторы» (в карточке: поле «кг» × поле «повт.»),
  у каждого подхода есть отметка «разминка» (разминка не входит в объём).
  «+ подход» копирует предыдущий.
- **Автосохранение**: кнопки «Сохранить» нет, любая правка уходит в IndexedDB
  через 0,4 с; «‹» в шапке сохраняет сразу и возвращает к списку.
- **«Как в прошлый раз»** копирует упражнения и подходы из предыдущей тренировки;
  при добавлении упражнения в новую тренировку подходы сразу подставляются из истории,
  а под карточкой видна строка «В прошлый раз (дата): 60×8, 60×8».
- **🔥 рекорд** — если вес в подходе выше всех прошлых по этому упражнению.
- Удаление упражнения из справочника не ломает историю: в тренировке хранится
  копия названия (`exerciseName`).

## Экран «Продукты и блюда» (этап 3)

Две вкладки-«чипа» вверху экрана: **Продукты** и **Блюда**.

**Продукты** (КБЖУ на 100 г):

- базовый набор из `product-catalog.js` — **288 позиций в 15 группах** (мясо и птица,
  рыба, яйца, молочное и сыры, крупы и бобовые, хлеб и выпечка, овощи и зелень,
  фрукты и ягоды, орехи и семена, жиры и масла, соусы, сладкое, напитки,
  готовые блюда, спортивное питание). Значения усреднённые — их можно править;
- набор подставляется **один раз**: продуктов, которые вы удалили, приложение
  повторно не возвращает. Если нужно вернуть недостающие позиции, внизу списка
  есть кнопка «↻ Добавить недостающие базовые продукты»;
- при обновлении с этапа 1 дублей не будет: сравнение по названию (регистр, «ё/е»
  и лишние пробелы не важны), у старых записей просто заполняется группа;
- поиск по названию и фильтр по группам (чипы прокручиваются вбок);
- свои продукты: «+» в шапке → название, группа, ккал/белки/жиры/углеводы на 100 г.
  Дробные значения вводятся с запятой (12,5). Дубль по названию не создаётся;
- карточка продукта: КБЖУ плитками, «Изменить» и «Удалить».

**Блюда** — только ваши, готовых нет:

- «+» в шапке → название и число порций, дальше конструктор;
- ингредиенты добавляются из справочника в граммах, продукт можно заменить,
  нажав на его название в строке (граммы сохраняются);
- в блюде сразу видно КБЖУ **на всё блюдо, на 100 г и на одну порцию**;
  вес готового блюда можно указать вручную, иначе берётся сумма граммов;
- автосохранение каждой правки (кнопки «Сохранить» нет), «‹» в шапке — к списку;
- в ингредиенте хранится копия названия и КБЖУ продукта, поэтому блюдо продолжает
  считаться, даже если продукт удалили из справочника;
- в списке блюд: число ингредиентов, вес, порции, КБЖУ на 100 г и ккал на порцию.

## Экран «Питание» (этап 4)

Дневник питания за выбранный день.

- **Дата**: «‹» и «›» листают дни, нажатие на дату открывает календарь,
  рядом кнопка «Вернуться к сегодня». Под датой подпись «сегодня / вчера / день недели».
- **Итоги дня**: крупно «съедено из нормы» и полоска прогресса, ниже «Осталось N ккал»
  (или «Выше нормы на N ккал») и три полоски Б/Ж/У с фактическим значением и нормой.
  Норму считает `targets.js` по профилю (формула Миффлина — Сан Жеора, коэффициент
  активности и поправка на цель); если в профиле нет веса/роста/возраста, экран
  показывает только суммы и предлагает заполнить профиль.
- **Четыре приёма пищи**: завтрак, обед, ужин, перекус. В заголовке — ккал приёма,
  в строке записи — название, вес, Б/Ж/У и ккал.
- **Добавление**: «+ Добавить» в приёме пищи или «+» в шапке (тогда приём выбирается
  по времени суток). В шторке две вкладки — **Продукты** и **Блюда** — и поиск.
- **Количество**: для продукта вводится вес в граммах (по умолчанию 100 г),
  для блюда — порции или граммы (переключатель пересчитывает одно в другое),
  есть быстрые чипы и живое превью КБЖУ.
- **Правка и удаление**: тап по строке открывает то же окно количества;
  кнопки «Сохранить» и «Удалить из дневника». Пустое или нулевое количество не сохраняется.
- В записи хранится снимок КБЖУ на 100 г (`per100`) и граммы, поэтому дневник
  продолжает считаться, даже если продукт или блюдо удалили из справочника.

## Экран «Профиль» (этап 5)

- **Параметры тела**: вес, рост, возраст, пол. Значения сохраняются сами (через 0,4 с,
  кнопки «Сохранить» нет), после каждой правки норма пересчитывается на месте.
- **Проверка опечаток**: вес 30–300 кг, рост 100–250 см, возраст 10–100 лет,
  MET 1–15. Значение вне диапазона подсвечивает поле и **не** сохраняется;
  пустое поле считается незаполненным — тогда норму не посчитать.
- **Активность** — 5 уровней с коэффициентом к базовому обмену (1,2–1,9);
  **цель** — похудение / поддержание / набор массы.
- **Норма на день**: калории крупно, плитки Б/Ж/У, ниже BMR, TDEE и расход
  за час силовой тренировки (MET × вес × 1,05). Считает `targets.js` — те же числа
  показывает дневник питания.
- **Данные**:
  - «Сохранить копию в файл» — JSON со всеми шестью хранилищами
    (`sila-kbzhu-ГГГГ-ММ-ДД.json`);
  - «Показать JSON» — тот же текст в шторке с кнопками «Копировать» и «Скачать»
    (пригодится, если на iPhone скачивание недоступно);
  - «Загрузить из файла» — импорт с подтверждением: текущие записи заменяются
    данными из файла, профиль дополняется значениями по умолчанию;
  - «Удалить все данные» — полная очистка базы (профиль возвращается к 70/175/30).
- Бейдж в карточке «Данные» — версия сборки (`APP_VERSION` из `version.js`):
  по нему на iPhone видно, что service worker отдал свежие файлы.

## Экран «Итоги» (этап 6)

- **Сегодня**: три плитки — съедено (из дневника питания), потрачено (тренировки)
  и баланс «съедено − потрачено». Ниже словами: «в пределах нормы / выше на N /
  ниже на N ккал» и строка нормы с учётом тренировки
  (`норма + расход = дневной лимит`).
- **Период** — чипы «7 дней» / «30 дней» (по умолчанию неделя). Сводка:
  среднее в день, число тренировок, тоннаж, средний баланс, всего съедено
  и потрачено, отклонение от нормы (дефицит/профицит за дни с едой).
  Средние считаются только по дням, где есть записи, — простой дня не занижает их.
- **График «Калории по дням»**: столбики — съедено за день, пунктир — норма
  из профиля. **График «Тоннаж по дням»**: сумма «повторы × вес» по рабочим
  подходам (разминка не считается).
- **Прогресс упражнения**: выбирается из списка (по умолчанию самое частое
  за период). Ломаная по датам — максимальный рабочий вес за тренировку
  (если вес не указан — тоннаж упражнения), ниже рекорд и тоннаж за период.
- **Расход тренировки**: `ккал = MET × вес (кг) × длительность (ч) × 1,05`,
  MET и вес берутся из профиля — та же цифра, что «расход за час» в профиле
  (`calcWorkoutKcal` в `targets.js`). Оценка приблизительная.
- Графики рисуются на `<canvas>` с учётом `devicePixelRatio` (на iPhone чётко),
  перерисовываются при повороте экрана; при смене светлой/тёмной темы цвета
  берутся из CSS-переменных. Если данных нет — вместо графика пустое состояние.

## Хранилища IndexedDB (`sila-kbzhu`, версия 1)

- `exercises` — `{ id, name, muscleGroup }`, личный справочник (автозаполнения нет)
- `workouts` — `{ id, date, durationMinutes, note, createdAt, updatedAt,
  exercises: [{ exerciseId, exerciseName, muscleGroup, sets: [{ reps, weight, isWarmup }] }] }`
- `products` — `{ id, name, kcal, protein, fat, carbs, category, isDefault? }` (на 100 г)
- `dishes` — `{ id, name, servings, finalWeightGrams, createdAt, updatedAt,
  ingredients: [{ productId, productName, kcal, protein, fat, carbs, grams }] }`
- `meals` — `{ id, date, mealType, kind: 'product'|'dish', productId?/dishId?, name,
  unit: 'g'|'portion', amount, grams, portionGrams, per100: { kcal, protein, fat, carbs },
  createdAt, updatedAt }`
- `profile` — одна запись с ключом `main`: вес, рост, возраст, пол, активность, цель,
  MET и служебное поле `productsSeedVersion` (какая версия базового набора уже подставлена)

## Безопасность и приватность (этап 7)

Приложение работает как «чемодан без ручки»: всё нужное внутри, наружу — ничего.
Ниже — что именно проверено и чем это закреплено в коде.

### Личные данные в коде

В исходниках нет ни имён, ни адресов, ни телефонов, ни почты, ни токенов и ключей:

- `defaultProfile()` в `db.js` — демонстрационные 70 кг / 175 см / 30 лет,
  это стартовые значения, а не чьи-то реальные параметры;
- `product-catalog.js` — обычный справочник продуктов (КБЖУ на 100 г);
- `tools/make-icons.ps1` — только рисование иконок.

Всё, что вы вводите сами (вес, рост, возраст, названия тренировок, упражнений,
блюд, записи дневника), хранится **только в IndexedDB на устройстве**.

### Что приложение не делает

- не отправляет данные в сеть: `fetch` есть только в `sw.js` и только для
  собственных файлов приложения (`url.origin === self.location.origin`);
- не подключает внешние скрипты, стили, шрифты, картинки, аналитику, трекеры —
  в проекте нет ни одного ресурса `http(s)://` (единственный `http://` в файлах —
  `xmlns` у SVG-иконки, это пространство имён, а не запрос);
- не просит доступ к геолокации, камере, микрофону, контактам, уведомлениям;
- ничего не кладёт в cookie, `localStorage`, `sessionStorage` — только IndexedDB;
- не открывает внешние окна и не ставит ссылок `target="_blank"`.

### Что защищает код

| Механизм | Где | От чего защищает |
| --- | --- | --- |
| `Content-Security-Policy` | `index.html` | любые внешние загрузки: `default-src 'self'`, `connect-src 'self'`, `object-src 'none'`, `base-uri 'none'`, `form-action 'none'`. Даже если в данных окажется внешняя ссылка, браузер её не загрузит, а данные не смогут уехать на чужой сервер. Политика заканчивается `;` — так её не ломает антивирус (Kaspersky в Edge дописывает свои директивы в конец `content`) |
| `referrer: no-referrer` | `index.html` | адрес приложения (включая hash вкладки) не уходит в заголовке `Referer` |
| `escapeHtml()` перед вставкой в `innerHTML` | `ui.js` + все экраны (все 50 мест с `innerHTML` проверены) | XSS: `<img src=x onerror=…>` в названии продукта, блюда, тренировки или упражнения показывается как текст |
| Строки бэкапа выводятся через `value`, не `innerHTML` | `profile.js` | инъекция при просмотре/копировании JSON |
| Проверка импорта: ≤ 20 МБ, ≤ 200 000 записей, строки ≤ 500 символов, поля `__proto__`/`constructor`/`prototype` отбрасываются | `profile.js` | «подсунутый» файл: зависание, загрязнение прототипа, гигантские названия |
| `sanitizeProfile()`: числа зажимаются в допустимый диапазон, пол/активность/цель — только из списков | `profile.js` | подменённый профиль ломает расчёты нормы (`NaN`) |
| Service worker: только GET своего origin, Range и ответы 206 не кэшируются | `sw.js` | порча кэша, кэширование чужих ответов |
| `.gitignore` в корне рабочей папки закрывает всё, кроме `fitness-pwa` | `C:\Users\User\clineai\.gitignore` | случайная публикация выгрузок с персональными данными |

Названия из базы попадают в разметку **только** через `escapeHtml()`; числа
предварительно приводятся к `Number`. Атрибуты `data-*` содержат числа или
экранированные строки.

### Ограничения, о которых надо знать

- **Кто разблокировал телефон — тот видит данные.** IndexedDB не шифруется:
  защита здесь — код-пароль iPhone и «Экранный доступ».
- **Адрес приложения публичный, данные — нет.** На GitHub Pages лежит только код;
  база создаётся в браузере при первом запуске и никуда не уходит.
- **Файл бэкапа `sila-kbzhu-YYYY-MM-DD.json` не шифрован.** В нём весь дневник,
  вес и рост. Не отправляйте его в мессенджеры и в облака без шифрования
  и удаляйте лишние копии.
- **Приватный режим Safari** может блокировать IndexedDB — приложение покажет
  «База данных недоступна».
- Если устройством пользуются несколько человек, у каждого должен быть свой
  браузер/профиль: IndexedDB привязана к адресу сайта, а не к пользователю.

### Как удалить всё

- «Профиль» → «Удалить все данные» — очищает все хранилища и профиль.
- Полностью: удалить иконку с домашнего экрана, затем Safari →
  `Настройки` → `Safari` → `Дополнения` → `Данные сайтов` → найти адрес → удалить.
  Удаление иконки само по себе данные **не** стирает.

Изменения этого этапа подняли версию сборки до `stage-7` (см. `version.js`) —
по бейджу в «Профиле» видно, что на iPhone приехала именно эта версия.

## Иконки

Иконки уже сгенерированы. Пересоздать (PowerShell 5.1, без интернета):

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\make-icons.ps1
```

Скрипт рисует синий квадрат с белой штангой в размерах 180/192/512.
Мотив вписан в центральную безопасную зону, поэтому 512-иконка годится и как maskable.
`icons/icon.svg` — тот же мотив в векторе (используется как `rel="icon"`).

> Важно: `tools/make-icons.ps1` должен быть в кодировке **UTF-8 с BOM**, иначе
> PowerShell 5.1 неправильно прочитает русские комментарии.

## Офлайн-режим и обновления

`sw.js` использует стратегию **network-first**: сначала сеть, при успехе обновляется
кэш, без сети — отдаётся копия из кэша. Поэтому правки подхватываются без смены версии
кэша; `CACHE_VERSION` поднимают только для принудительного сброса кэша.

Все запросы к своим файлам уходят в сеть с `cache: 'no-cache'` (перепроверка по
ETag/Last-Modified): GitHub Pages отдаёт статику с `Cache-Control: max-age=600`, и без
этого после публикации можно до 10 минут видеть старую версию из HTTP-кэша браузера.

Если на iPhone видна старая версия: закройте приложение полностью и откройте снова —
при запуске вызывается `registration.update()`, а при смене service worker появляется
тост «Пришло обновление».
